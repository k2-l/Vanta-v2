# Vanta Desktop GUI 定稿规范

状态：**Approved / v1.0**

定稿日期：2026-09-14

适用范围：`desktop/` Tauri 2 客户端

实现进度同步：2026-09-15，依据当前未提交工作区。设计基线保持 **Approved / v1.0**；当前实现差距见 §8，阶段进度见 [实施 Plan §2](./tauri-desktop-implementation-plan.md#2-当前基线)。

## 1. 设计结论

Vanta Desktop 采用独立的桌面端视觉与交互体系，**不沿用现有 Web 页面样式**。Web 与桌面端只共享业务概念、协议契约和后端能力，不共享页面布局与组件外观。

设计目标：

- 对话是首要工作入口，运行、审批和产物形成连续任务链路。
- 重要状态在当前上下文中可见，不依赖频繁跳页。
- 高风险操作必须展示来源、范围和影响，再由用户明确确认。
- Rust Core 持有连接与凭据；WebView 不展示或持久化敏感信息。
- 界面保持克制、专业和高信息密度，避免营销式大卡片与移动端式导航。

## 2. 全局信息架构

桌面窗口采用四层结构：

| 区域 | 基准宽度 | 职责 |
|---|---:|---|
| 标题栏 | 高 42 px | 工作区身份、活动连接、窗口拖动区域 |
| 全局导航栏 | 58 px | 六个一级模块及全局未读状态 |
| 上下文侧栏 | 218 px | 当前模块的对象列表、筛选和局部状态 |
| 主工作区 | 自适应，最小 360 px | 当前任务的主要内容与操作 |
| 详情面板 | 250 px，可关闭 | 运行轨迹、元数据、上下文用量和关联产物 |

一级模块及顺序固定为：

1. 对话 Chat
2. 运行 Runs
3. 审批 Approvals
4. 产物 Artifacts
5. 能力 Capabilities
6. 设置 Settings

详情面板在对话、运行和审批模块中按需出现；产物、能力和设置默认使用完整主工作区。

## 3. 视觉语言

### 3.1 色彩

- 默认主题：深色；同时完整支持浅色。
- 品牌强调色：紫色 `#6657EE`，仅用于选中态、主操作和活动运行状态。
- 成功：`#35BD78`；警告/审批：`#E4A03B`；失败/危险：`#E05F63`。
- 深色背景分为窗口、导航、内容、浮层四级，不使用纯黑。
- 正文、次要文字和辅助文字必须维持三个清晰层级。

现有 `desktop/src/styles/tokens.css` 是实现入口；实现阶段应扩展 token，而不是在页面中散落色值。

### 3.2 字体与密度

- UI 字体：系统无衬线字体栈，中文优先使用 PingFang SC / Microsoft YaHei。
- 代码和路径：系统等宽字体栈。
- 页面标题 15–18 px；正文 12–14 px；元数据 9–11 px。
- 常规控件高度 30–34 px；列表行高 42–52 px；圆角以 6、8、10、12 px 四档为主。

### 3.3 状态表达

- 颜色不是唯一信号；状态同时包含文字、图标或形状。
- 运行中使用紫色脉冲点；完成使用绿色实心点；审批使用琥珀色徽标；失败使用红色标识。
- 加载、空、错误、离线、无权限和能力不支持必须有独立页面状态。

## 4. 模块定稿

### 4.1 对话

- 上下文侧栏展示会话搜索、时间分组、运行状态和新建入口。
- 主工作区由会话标题、消息流、步骤卡片、工具事件和输入器组成。
- 用户消息弱强调；Agent 消息使用开放布局，不使用大面积气泡。
- 流式响应内联展示步骤状态；停止按钮只在运行期间出现。
- 右侧运行详情展示 Run ID、状态、耗时、Token、执行轨迹和关联产物。

### 4.2 运行

- 上下文侧栏按状态和时间范围筛选。
- 主工作区使用高密度运行列表，行内展示 Agent、步骤/工具数、Token、耗时和状态。
- 选择运行后，右侧详情展示 Agent 树、事件时间线、预算和可执行操作。
- 断线重连后按 sequence 恢复事件；不能恢复时明确标记数据缺口。

### 4.3 审批

- 上下文侧栏区分待处理、已批准、已拒绝和已过期。
- 审批卡必须展示请求来源、风险等级、操作对象、作用范围和预计影响。
- 主按钮文案描述授权范围，例如“允许本次”；禁止使用含糊的“确定”。
- 拒绝和批准都需形成可追溯记录；过期审批不可再次提交。

### 4.4 产物

- 上下文侧栏按类型与来源筛选；主工作区采用“产物列表 + 预览”布局。
- 产物显示名称、类型、大小、来源会话和更新时间。
- 文档、图片和文本支持内置预览；未知或高风险类型只显示元数据。
- 导出必须经过 Rust Core 的安全路径选择与能力检查。

### 4.5 能力

- 上下文侧栏按 Agent、技能、MCP、知识库和执行环境分类。
- 主工作区按来源分组展示可用性、数量、同步时间和运行位置。
- 能力详情必须区分“已发现”“可用”“不可用”“需配置”。
- 桌面端只呈现后端已声明的能力，不用静态占位伪装可用功能。

### 4.6 设置

- 设置分为连接、外观、通知、快捷键、更新、诊断与日志、关于。
- 连接页是首屏，展示服务地址、延迟、协议版本和认证状态。
- 明确提示“凭据只由本机 Rust Core 保管，不进入 WebView”。
- 按当前开发联调决策，本机及远程地址均允许 HTTP；上线前切换为 HTTPS 并收口生产连接策略。当前联调地址为 `http://10.1.1.2:8765`。
- TLS 选项仅在 HTTPS 地址下显示；HTTP 不读取历史 CA 路径。HTTPS 保留现有信任策略与证书校验，系统根证书接入及服务器证书用途问题仍须在上线前修复。
- 危险操作使用弱化红色文本按钮，并与常规操作分离。

## 5. 交互与窗口适配

- 基准验收尺寸：1280 × 720；推荐最小窗口：960 × 640。
- 宽度低于 1100 px 时优先关闭详情面板；低于 900 px 时压缩上下文侧栏。
- 键盘可访问所有导航、列表和主要操作；焦点环不得被移除。
- `⌘/Ctrl + K` 聚焦当前模块搜索；`⌘/Ctrl + N` 新建对话；`Esc` 关闭浮层或详情。
- 动效时长控制在 120–220 ms；支持系统“减少动态效果”。
- 列表切换不丢失滚动位置；切换模块时保留各模块最近选择。

## 6. 组件边界

实现阶段应沉淀以下桌面组件，而不是从 Web 端复制页面组件：

- `DesktopTitleBar`
- `GlobalNavRail`
- `ContextRail`
- `ContentHeader`
- `DetailPanel`
- `StatusDot` / `StatusBadge`
- `ResourceList` / `ResourceRow`
- `RunTimeline`
- `ApprovalCard`
- `ArtifactPreview`
- `DesktopComposer`
- `EmptyState` / `ErrorState` / `OfflineState`

组件只接收已经归一化的前端 view model；远程请求、凭据和路径授权继续由 Rust Core 处理。

## 7. 验收基线

GUI 实现必须同时满足：

- 六个一级模块与本规范的信息架构一致。
- 1280 × 720 和 960 × 640 下无关键内容截断。
- 深浅主题均达到清晰可读的对比度。
- 键盘可完成导航、发送消息、处理审批和关闭详情。
- 所有真实状态来自契约或 Rust Core，不硬编码虚假在线/可用状态。
- 敏感字段不进入浏览器存储、前端日志或可复制诊断信息。
- 空、加载、错误、离线、无权限和能力不支持状态均可走查。

本文件是 GUI 视觉与交互的唯一设计基线。若实现与本文件冲突，应先更新并重新确认本文件，再修改代码。
