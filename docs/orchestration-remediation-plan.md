# 编排系统整改计划与实施记录

> 基线：`docs/orchestration-review.md` 的 14 项问题逐项复核结果。
> 范围决策：本轮只改后端；前端问题与向量数据库类型/历史数据问题登记为延期项。
> 最终编排约束：主代理与子代理都可使用 `Agent`；每个 agent invocation 最多同时运行 3 个直接子代理；最大委派深度为 3。

## 设计口径

### 委派边界

- 主代理深度为 0，子代理允许进入深度 1、2、3；深度 3 不得继续委派。
- “委派上限 3”是按父 invocation 独立计算的并发槽，不是整回合累计次数；子调用结束后释放，因此支持超过 3 段的串行流程。
- 默认整棵树容量为 `3 + 9 + 27 = 39` 个子 invocation；全局计数只作为异常膨胀护栏。
- 每个 invocation 使用基于 tool-call ID 的稳定路径标识，事件携带该 `task_id`，同名并行 agent 不再在后端合并为同一来源。
- 禁止调用链内循环委派同一 agent，避免 `A → B → A` 类递归环。

### Token 预算

- 主代理 invocation 与每个子代理 invocation 分别维护自己的 `invocation_tokens/token_limit`，父子和兄弟之间不转移、借用或扣减余额。
- `main_agent_token_limit` 与 `sub_agent_token_limit` 分开配置。
- 原有 session/day 限额保留为全局硬熔断和累计记账，不作为各 agent 的共享可分配余额。
- 每次主代理、子代理和 critic 模型调用前检查全局硬熔断；每次调用后累计到当前 invocation。
- invocation 预算或工具迭代上限耗尽后，补齐悬空 `tool_result`，切换到不绑定工具的模型做一次强制总结，避免 recovery 打转。

## 问题逐项整改

|---|---|---|---|
| B1 | 确认 | 后端新增完整文本与分块流式内部区段过滤器；主/子代理状态、SSE、DB 与记忆只接收公开正文 | 任意 chunk 边界的 `scratchpad/subgoal` 均不外泄 |
| B2 | 确认 | `AgentFull.enable_critic` 从 frontmatter/provider 接入子图；按开关注册 critic 节点和路由；兼容纯 JSON、Markdown 围栏及前置说明文字 | 开启时路径为 `agent → critic`，常见模型 JSON 输出格式均能进入质量判定 |
| B3 | 确认 | 子代理始终可见 `Agent` 工具；统一直接并发上限 3、深度上限 3，并加调用链环检测 | 深度 1–3 可达；同一父代理同时最多 3 个子调用，串行完成后可继续委派 |
| B4 | 确认 | 每次模型调用前复核全局熔断；新增 invocation 独立预算；默认工具调用与循环上限改为正数 | 单回合不能依赖 500 层图递归才停止 |

| B6 | 确认 | 后端事件增加 invocation `task_id`，同名并行调用也能区分 | 每个子代理文本/工具事件均带独立来源 ID；前端分栏延期 |
| B7 | 确认 | 实时过程可继续流式展示，但只把最终无工具调用轮次保存为 assistant 正文 | DB/记忆不再拼接中间轮文本 |

| B10 | 确认（潜在） | 配置入口拒绝 0/负数；预算百分比保留除零防御 | 非法配置返回 422，旧异常配置不触发 500 |
| O1 | 确认 | 所有成功工具输出在进入模型和落盘前统一脱敏；目录/文件权限分别为 0700/0600 | 非 engagement 输出也不会以未脱敏、宽权限形式落盘 |
| O2 | 确认 | 并行任务完成后按合并计数生成一次失败提示 | 同轮同名工具多次失败显示最终累计次数 |
| O3 | 确认 | 廉价估算改为 CJK 感知系数，消息估算复用同一算法 | 中文估算不再固定 `len/4` |
| O3b | 确认 | 检测未压缩且超出回退窗口的消息数，向模型上下文和任务日志注入明确覆盖缺口 | 不再静默假装拥有完整历史；相关任务会提示先压缩 |

## 延期但保留的问题

### 前端

- 增加 `scratchpad` 的展示层纵深防御。后端现已过滤，但前端仍应避免将未来其他来源的内部标签直接渲染。
- 按 `task_id` 对并行子代理文本、工具卡和阶段进行分组/分栏。目前后端协议已提供标识，前端消费暂不修改。

### 向量数据库

- 向量数据库的类型/schema 与历史数据清理本轮不处理。
- 本轮仅从写入源头阻止新的 scratchpad 和中间轮噪声进入记忆；既有向量记录不迁移、不重建、不清洗。

## 实施阶段

1. 已完成：隐私边界、最终答复持久化语义、工具输出安全。
2. 已完成：递归委派上下文、次数/深度/循环护栏、独立 token 预算。
3. 已完成：critic 接线、混合模型成本、并行失败计数、配置校验、历史覆盖提示。

5. 延期：前端按来源渲染；向量库类型和历史数据治理。
